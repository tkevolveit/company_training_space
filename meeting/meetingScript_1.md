5. 躓いた点
次は躓いた点です。

今回の画面作成で躓いた点ですが、

z-indexとスタッキングコンテキストの関係です。

今回の画面作成で躓いた点ですが、
z-indexとスタッキングコンテキストの関係です。

何をしたい時に発生したのかですが、
テキストの後ろに画像を配置しようとした所、
画像がテキストの上に表示され上手く配置できない事で躓きました。


原因ですが、
z-indexを効かせたい時は、
要素にpositionを指定する必要があったのですが、
positionの記述がなかったのが原因でした。

なので要素にpositionを指定したところz-indexが適用され画像と文字をスタックすることが出来ました。

また、Flexbox かグリッド レイアウト内で Z-Index を使用した場合は、position: relative がなくても機能するということが調べて分かりました。

## 工夫した点
次は工夫した点です。
今回の画面作成にあたり、本からの知識と自己学習で身に着けた知識で工夫しながら作成を致しました。

1)
#### rem
テキストではpxの使用でしたがremを活用しています。
pxだけの指定ですとユーザーの拡大設定が無効になり、可読性やアクセシビリティが損なわれるので、remで基本スケールを管理しつつ、必要な部分にだけpxで固定値を与えるというやり方をしています。

固定の値の見た目にしたい箇所はpxで、
画面サイズに対応させたいところはremを使用しています。

ADDITIONAL NOTE
remなのですが、ルート要素（html）に指定されたfont-sizeを基準にサイズが決まります。
1rem=16px がブラウザの初期設定

またem unitであるのですが使用していません、
emは親要素に対する相対指定 → ネストが深いとサイズが崩れやすい為、管理しやすいremを使用しています。


＊remはルート要素に対する相対指定 → 一貫性が保ちやすい

- pxは画面上のピクセルに基づく絶対単位です → ユーザー設定に影響されない
- emは親要素に対する相対指定 → ネストが深いとサイズが崩れやすい
- remはルート要素に対する相対指定 → 一貫性が保ちやすい

2)
CSS Modern Featuresを活用し、
CSS NestingでCSSの記述をしています。
CSS Nestingは、CSS定義のネスト（入れ子）記述を可能とするCSS構文です。
CSS Nestingを用いると、関連性の近いスタイルがわかりやすく、また記述の重複が削減出来るので活用しました。




OPTIONAL
Viewportの説明
<meta name="viewport" content="width=device-width, initial-scale=1.0">
Viewport設定はレスポンシブ対応の要であり、@mediaクエリの正しい動作に必須
このメタタグではViewportの幅をデバイスの画面幅（CSS px単位）に合わせ、ページの初期ズーム倍率を 1.0 に設定するようになっています。
